# 已就绪生产的技术路线与关键技术验证

## 业务边界

研究对象为已由上游确认满足生产条件、进入厂内作业阶段的任务。工艺文件、人员、设备资格、物料及工装等前置条件由上游业务流程确认；原型使用 `production_ready=true` 表示这一确认，并独立检查已确认的当前库存和备料状态。该标记不等于系统已经自动核验全部现场条件。

Planning 负责已准入任务的工单调整、资源约束与局部优化，不配置预测模块，不承担库存、到货、采购或市场需求预测。未满足准入条件的任务返回 NOT_ADMITTED；库存修正和到货延迟事件在主框架返回 OUT_OF_SCOPE。库存未来到货不用于满足本次准入。

Warehouse 在当前范围中承担已确认就绪信息的复核、厂内物料分配一致性检查及人工复核，不进行库存预测。共享算法中保留的到货处理用于独立实验，不能作为当前主路线的业务能力。

## 调整后的路线

上游生产就绪确认 → Orchestrate 设备与作业风险前瞻 → 下游上下文预初始化 → 确认事件与版本 → Planning 工单调整 → Scheduling 工序安排 → Warehouse 当前就绪复核 → 各模块人工复核 → 独立约束与版本校验 → 模拟 MES 写回。

Orchestrate 持有 `OperationsPrediction`。本次实现只根据已知未来设备窗口检查基线占用冲突，不预测未知故障，不预测库存。后续可扩展为基于工序进度和设备状态趋势的风险预测，但须通过独立数据验证。

所有四类模块均有自己的人工复核请求和输出内容。可能改变计划的候选必须获得四个模块针对同一上下文和最终方案的批准；任一拒绝则停止写回。保持原计划、未准入和越界事件只返回建议/原因，不下发生产变更。预测和预初始化都是只读准备，不需要也不能借此取得执行授权。

## 关键问题与拟解决技术

| 关键问题 | 本阶段关键技术 | 验证依据 |
|---|---|---|
| 扰动发生前能准备什么 | 已知设备窗口冲突检查与影响范围定位 | 前瞻结果列明设备、工单、风险时刻和提前量 |
| 准备工作是否实际复用 | 固定工单/物料占用与局部问题构建缓存，排单资源映射、就绪工单索引 | 正式求解报告 cache_hit，输出与冷启动方案一致 |
| 预测与确认不一致时如何处理 | 完整状态、基线版本、工单状态和局部范围联合键 | 窗口、版本或状态变化立即失效并重建 |
| 人如何参与每个模块 | 按模块记录的本地人工复核账本，绑定上下文和最终候选 | 缺审批、拒绝、审批对应其他方案时网关拒绝 |
| 范围缩小后如何保持约束 | 显式就绪准入、冻结在制品、范围外计划保留 | 未就绪任务不以等待未来物料的方式排入生产 |

## 已实现关键技术

首项技术为“基于前瞻事件的多模块上下文预初始化及一致性复用”。实现位于 `agents/prediction.py`、`agents/orchestrate.py`、`capabilities/local_search.py`，人工复核位于 `infrastructure/review.py`。

预初始化实际构建固定工单占用、物料分配后的局部问题、设备日历映射及就绪工单索引。正式事件到来时，状态键完全一致才复用，避免将未经确认的预测方案直接执行。预初始化不提前输出优化决定，也不修改 MES。

演示输入 `examples/operations_ready.json`：M1 在未来第30至45分钟不可用；原基线 WO-NORMAL 在20至50分钟加工，产生可预见冲突。预初始化后，已在制的 WO-RUN 仍为0至20，WO-NORMAL 调整到45至75，另一机台的 WO-OTHER 保持80至90。所有任务的生产条件均已确认。

```powershell
# 人工交互演示：逐个查看四类模块输出并输入审核人及 y/n
python -m enterprise_agent operations-demo
# 可选：使用本机配置的真实 LLM 提案，仍须逐模块人工审核
python -m enterprise_agent operations-demo --agent llm
# 无人工输入时展示待复核和不写回
python -m enterprise_agent operations-demo --review-mode pending
# 自动复现协议测试：所有批准均明确标记为模拟
python -m enterprise_agent operations-demo --review-mode scripted --output artifacts/operations-scripted.json
```

查看 summary 中的提前量、预初始化后的 MES 版本、三类缓存是否复用、与冷求解结果是否一致、各模块复核状态及最终版本。`scripted` 只允许内存演示网关接受模拟批准，不能宣称已有人类审核。

## 验证范围与限制

本次验证“准备了什么、是否复用、变更时是否失效、审批是否阻断”。单个小型合成算例的耗时只作描述，不宣称工业规模加速百分比。正式效益验证需要同等资源、相同结果质量下的多规模冷启动/预初始化对照，分别记录准备阶段、事件到来后的求解阶段和人工等待时间。

演示仍采用单决策时刻，预告与确认按调用顺序发生；30分钟是已知设备窗口的场景提前量，不代表程序已经等待30分钟或实现连续生产仿真。人工复核账本只驻留内存，审核人是本地输入名称，尚未对接企业身份认证、持久化审批与消息投递。

LLM 仍是可选协调提案源，不能批准或绕过复核；真实模型联调未验证。CP/MILP、MARL 和真实 MES 接口不属于当前已完成的技术实现。
