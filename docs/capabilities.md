## LLM 边界

框架模型只返回 `action`、`scope` 和简短业务理由。范围必须与门卫判断一致，模型不能压下强制处理事件或批准安全动作。处理与校验由程序执行，失败退回规则。另有旧实验入口允许模型通过有限工具循环探索候选，与框架提案入口分开。

请求使用总时间/输出限制，HTTP 禁止重定向以避免密钥转发。报告不记录密钥或原始供应商回复；思维模型所需的临时 reasoning 字段只在工具交互内存中重放。结构化业务提案及证据可能进入审计，因此使用真实数据后生成的输出也需自行保护。

## 学习策略边界

`MARLPolicy` 用于未来多设备或多工位策略。激活需要匹配策略 ID 的模拟/历史回放证据，相关指标不能恶化。即使有离线证据，实际候选仍需独立约束校验，并与确定性候选比较；不合格时拒绝或回退。证据对象目前来自受信任的调用方，没有报告签名或发布审批平台。

现有 DQN 使用静态工单派工环境，选择下一工单的派工规则。它没有模拟真实执行过程，也没有完整工厂状态观测。单智能体训练不能称为 MARL，不能据训练成功宣称策略优于固定规则或具有生产收益。

## 后续实施依赖

1. 对齐真实 MES/WMS 字段与确认协议，补持久化事件、执行反馈和历史回放。
2. 接入 CP/MILP，分离 WO 粗计划与 OP 微调，加入换型、已消耗物料和部分完工。
3. 完成真实 LLM 联调、审批身份与可恢复抢占模型。
4. 建立多资源仿真、独立观测与联合奖励，再实现并评测 MARL。
5. 引入校准的概率预测与诊断证据，验收感知延迟、处理时间、备料命中率和人工干预率。

演示中的优先级权重和处理时间目标是配置示例，不是已达成的性能指标。
