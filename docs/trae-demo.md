# Orchestrate 监控与前瞻机制：Trae 演示流程

建议用时：5—7 分钟。

本次要展示的是：**Orchestrate 接收未来扰动假设后，按需提前准备下游模块的计算上下文，并保留人工复核和历史记录。**

当前使用“模拟演示（不调用大模型）”：风险回复由程序预先提供，后续模块初始化、复核和持久化流程实际运行。它验证工程流程，不证明大模型能否准确预测扰动。真实 LLM 接口已接入，实际调用和效果验证留待后续联调。

## 1. 会前准备

1. 在 Trae 打开仓库中的 `MAPS-demo.code-workspace`。
2. 打开 **Terminal / 终端** 面板，新建两个终端，分别用于后端和前端。终端输入命令，AI 对话框用于交流，两者用途不同。
3. 确认两个终端都位于项目根目录，能看到 `enterprise_agent`、`frontend`、`run_platform.ps1` 和 `.venv`。
4. 如果演示页面已能打开，可以直接进入第 3 步，继续使用当前服务。

本机已准备好 `.venv`。换一台电脑时，应在会前完成环境安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[web,web-test]"
```

## 2. 在 Trae 中启动服务

终端 A 启动后端：

```powershell
.\run_platform.ps1 -Role api -WithFixtures
```

看到以下信息，说明后端已启动：

```text
Uvicorn running on http://127.0.0.1:8000
```

终端 B 启动前端：

```powershell
.\run_platform.ps1 -Role ui
```

看到以下信息，说明前端已启动：

```text
MAPS UI: http://127.0.0.1:5173
```

也可以在 Trae 的“运行任务”中依次选择：

- **平台 01 后端API与任务运行时（模拟演示，不调用大模型）**
- **平台 02 独立前端**

两个服务保持运行。页面刷新不会启动服务，关闭启动它的终端可能使页面无法访问。

## 3. 打开工作台，说明本次演示范围（约 30 秒）

在 Chrome 打开完整地址：

<http://127.0.0.1:5173/>

页面右上方应显示“API 已连接 · 2 个任务槽”。在“推理来源”中选择 **模拟演示（不调用大模型）**。

现场讲法：

> 本周重点是 Orchestrate 的监控与前瞻机制。今天先用模拟回复，展示未来扰动假设如何触发下游模块提前准备，以及人工复核和记录回放。真实模型的判断能力还需要单独验证。

## 4. 创建任务，展示监控输入和风险假设（约 1 分钟）

点击 **＋ 新建监控任务**，等待任务状态变为“待人工复核”。

先看“运行观测”：

| 观测时刻 | 工序进度 |
|---|---|
| t=0 分钟 | 0% |
| t=10 分钟 | 12% |
| t=20 分钟 | 24% |

再看“Prediction · 未来扰动与证据”：模拟回复包含加工超时风险、预计影响窗口、观测依据，以及对 Planning、Scheduling、Warehouse 的准备请求。

现场讲法：

> 输入是当前状态和历史加工进度。Prediction 的输出包含未来风险假设、引用的观测证据，以及需要提前准备的模块。本次风险回复预先写好，后续处理按真实程序执行。

这里的风险时间窗口和不确定性属于模拟回复，不作为已经发生的事实或预测准确率。

## 5. 重点展示“模块提前初始化”（约 1 分钟）

向下查看“按需初始化与人工复核”。当前示例应显示 3 个模块已准备：

| 模块 | 实际准备的内容 | 页面中的结果 |
|---|---|---|
| Planning | 局部求解问题及固定占用上下文 | `local_solver_problem · CONTEXT_READY` |
| Scheduling | 设备资源日历 | `resource_calendar · CONTEXT_READY` |
| Warehouse | 当前工单索引 | `current_order_index · CONTEXT_READY` |

现场讲法：

> 这里体现了“其他模块可以提前初始化”：Orchestrate 根据预测输出中的模块请求，实际构建对应计算上下文，供后续作业调整使用。当前准备过程只读，尚未优化并下发生产计划。

同时指出：页面显示 **MES 未写回**。本版还没有用真实生产事件验证这些准备能节省多少响应时间，现场不承诺加速比例。

## 6. 逐模块人工复核（约 1 分钟）

1. “本地复核人”填写 `演示复核人`。
2. “复核意见”填写 `已核对观测依据与提前准备范围`。
3. 依次确认 Orchestrate、Planning、Scheduling、Warehouse。
4. 查看任务状态变为 **复核通过**。

现场讲法：

> Orchestrate 及本轮实际初始化的模块都保留人工复核。这里确认的是准备结果；复核通过仍不会自动下发生产指令。本地复核姓名用于演示记录，尚未接企业身份认证。

## 7. 回放前后两个时刻，展示调用顺序（约 1 分钟）

进入“持久化事件与历史回放”：

1. 选择名称为 `artifact.prediction` 的事件，点击 **读取历史状态**。此时已有风险假设，**已初始化模块数量为 0**。
2. 选择名称为 `artifact.preparation` 的事件，再次点击 **读取历史状态**。此时 **已初始化模块数量为 3**，模块上下文已经准备完成。
3. 点击 **返回实时**，恢复查看当前复核结果。

按事件名称选择即可；编号会随任务增长，不必固定寻找 `#5` 或 `#6`。

现场讲法：

> 这两个时点展示了执行顺序：先得到预测输出，再准备下游模块。回放读取已保存的记录，不重新调用模型，也不重新运行任务。

## 8. 回到 Trae，定位关键实现（约 1 分钟）

打开 `enterprise_agent/agents/orchestrate.py`，重点看两个方法：

| 位置 | 讲解重点 |
|---|---|
| `monitor()` | 先调用 `_observe()` 完成观察和预测，再根据 `should_prepare` 决定是否准备模块 |
| `_initialize()` | 根据 `requested_modules` 及必要依赖，实际调用下游准备接口 |

需要展开时再看：

- `enterprise_agent/agents/prediction.py` 中的 `LLMPrediction`：真实模型调用与结构化输出校验。
- `enterprise_agent/application/protocol_fixture.py`：本次演示所用的预设模拟回复。
- `enterprise_agent/application/task_runtime.py`：任务进程、超时和重试。
- `enterprise_agent/infrastructure/task_store.py`：保存观测、预测、准备结果、复核和回放记录。

结束时可这样概括：

> 本周已跑通 Orchestrate 从监控、接收未来扰动假设到按需提前准备模块的工程链路，并接入逐模块复核与持久化。下一步在同一接口上开展真实 LLM 调用，评价风险判断和模块选择是否合理。

## 可选演示与现场问题处理

### 展示持久化

有时间时，在后端终端按 Ctrl+C，再用原命令启动。刷新工作台并选中原任务，查看报告和复核记录仍然存在。重启时继续使用同一数据库路径。

### 页面超时或“API 未连接”

分别打开：

- 前端：<http://127.0.0.1:5173/>
- 后端状态：<http://127.0.0.1:8000/api/health>

使用完整的 `http://` 地址。后端状态应返回 JSON。`8000` 是接口端口，工作台页面在 `5173`；访问 `8000` 根路径出现 404 不表示服务超时。

检查对应终端是否还在运行，以及是否出现启动错误。浏览器能够打开前端但显示“API 未连接”时，优先检查后端终端。

### 提示端口被占用

说明该端口已有服务。先访问对应地址确认是否可直接使用；需要重启时，在启动该服务的终端按 Ctrl+C，再重新启动。

### 脚本无法执行

在 Trae 两个终端中直接运行 Python，效果相同：

```powershell
# 终端 A
.\.venv\Scripts\python.exe -m enterprise_agent platform-api --allow-protocol-fixture

# 终端 B
.\.venv\Scripts\python.exe -m enterprise_agent platform-ui
```

### 需要展示测试

可运行 Trae 任务 **平台 03 运行时与API测试**，或在第三个终端运行：

```powershell
.\run_platform.ps1 -Role test
```

测试使用模拟回复，不会调用真实模型。主汇报优先展示业务流程和初始化结果，测试输出作为补充证据。
