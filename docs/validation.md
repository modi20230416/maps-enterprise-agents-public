## 回归验证

开发版和通用公开版各运行 `python -m unittest discover -s tests -q`，均通过75项测试。验证覆盖四模块分别拒绝、缺少审核、其他方案审核、待审核后重试、模拟批准网关隔离、设备窗口或版本变化导致准备上下文失效、未就绪任务准入拒绝，以及提案源收到厂内风险但不获得批准权限。

## 演示顺序

1. 说明业务范围：任务前置条件已由企业确认，Planning不预测库存或到货。
2. 展示输入中的设备窗口和原计划，指出可预见的冲突。
3. 运行 `python -m enterprise_agent operations-demo --review-mode pending`，展示准备内容、复用标记、候选结果和MES未变化。
4. 运行 `python -m enterprise_agent operations-demo`，现场逐一查看四模块输出，输入本地审核人及y/n。此交互步骤由演示者实际操作；测试中的自动批准不算人审。
5. 用测试说明版本/状态变更时的失效与拒绝分支，给出企业数据接入和多规模比较的下一步。

## 实际限制

这是单决策时刻的原理验证；前瞻与确认按调用顺序发生，没有连续工厂时钟。提前30分钟是场景中的窗口距离。未验证未知故障预测、工业规模加速、真实MES、企业身份认证或持久化审核。75项测试不等于项目指南提出的期末规模和性能指标已经达到。

可用 `operations-demo --agent llm` 接入本机配置的模型作为结构化提案源；本次结果使用规则提案，真实模型联调未验证。DQN仍作为独立实验，MARL只有接口，尚无学习策略生产收益证据。
